# 盲评手册

每次只看 review.json 中的一题，先读 input 和 rubric，再读 left 与 right。先独立判断两边是否可交付，再比较教学质量。左右位置每题都可能变化。

| 功能 | 核对顺序 | 严重错误举例 |
|---|---|---|
| Grammar | 找出必要更改，接受语义等价的多种正确答案。核对无错句的 correction 为空、有错段落完整、编号和数字保留；再看 refine 是否自然、解释能否帮助学习者理解改动。 | 教错规则、改变时间或金额、把学习者原本正确的表达断言为错误。 |
| Ask | 先核对首段是否答到当下的问题，再检验规则、例句、回答语言和固定历史。只有例句能澄清选择时才给它加分。 | 错误规则导致错误示例；忽略上下文而给出相反解释。 |
| Coach | 对每个主要判断追溯 input.entries 的 entryId 和原文。检查提示使用、重复尝试、模型改写和反例。最后判断建议能否针对具体弱点执行。 | 虚构引文、把参考答案归给学习者、凭一次提示作答断言掌握。 |

## 每票怎么填

winner 取 left、right 或 tie。severeLeft、severeRight 分别填 true 或 false，reason 写出决定性原句或证据及判断理由。平局可表示两边同样好或同样差，请在 reason 中说明。一个可填写的例子如下：

```json
{"id":"grammar-1","winner":"right","severeLeft":true,"severeRight":false,"reason":"左侧把已结束的居住经历强改为现在完成时；右侧保留 lived。"}
```

例子只示范格式；请以当轮随机分配的答案为准。一边生成失败时可交付的一边胜；两边都失败时记平局。单纯的 HTTP 或格式失败已经计入交付失败，严重错误栏用于教学内容。格式有效但答错仍然可以标为严重。不要因一方更长或标题更多就判胜。

第二位评审复核全部严重错误以及随机 20% 普通题；单人评估可隔日复评，记录复核人和分歧裁决。按任务在一轮结束后统一揭盲。新增严重错误按同题 B 有、A 无计算；两边都严重但错因不同的配对还需人工逐项审查。

## 解读结果

净胜率为（B 胜数 − A 胜数）/ 全部配对数。异模型配对保留在总数，单列且不投胜负票，须补测后再决定。首次成功表示一次模型调用后通过交付检查；最终成功包含 Coach 校验重试。调用失败及重试均计入耗时。正确性、语义保真、证据支持度与回答语言须人工判断。正式集适合比较这批任务上的输出，长期学习效果需要另外收集延迟迁移题的表现。
